- Status: **LOCAL AND HOSTED LINUX CI PASS**
- Verified: 2026-07-20
- Scope: T001 and T002

## Runtime and install

- Node `v24.18.0` and npm `11.16.0` were run from an official archive whose SHA-256 matched the
  published checksum.
- A disposable clean `npm ci` installed 443 packages under strict lifecycle-script denial.
- `npm approve-scripts --allow-scripts-pending` returned `No packages with unreviewed install
  scripts.`
- `.python-version` pins Python `3.14.6`. The full local gate ran under the native arm64 Astral
  portable build with archive SHA-256
  `35d774f61d63c1fd4f1bc9495a7ada92e500dc4382a0df8a9910eb87ea48e8cf`.
- `scripts/bootstrap-macos-arm64-runtimes.sh` records the exact disposable Node/Python URLs,
  checksums, extraction, and version assertions; it does not change the user's shell profile.

## Core gate

`npm run check` passed in the canonical worktree and a clean-install copy:

- Prettier check
- ESLint with zero warnings
- strict TypeScript check
- 11 Vitest unit cases
- 3 repository-contract integration cases
- 24 Python proof cases
- independent Node verification of 5 end-to-end and 4 primitive cell-ID vectors
- documentation link/status check across 27 Markdown files
- Next.js 16.2.10 production build with seven routes

The clean-copy build initially failed only because the restricted execution sandbox denied
Turbopack permission to bind an internal local port. Re-running that exact build with the required
local permission passed; this was an execution-environment denial, not an application failure.

## Browser baseline

Playwright `1.61.1` installed its pinned Chromium `149.0.7827.55` and Firefox `151.0` builds in a
disposable `/private/tmp` directory. The suites passed against both the local development server and,
with `CI=1`, the optimized production server:

- 2 Chromium E2E cases for the honest demonstration read path and invalid route boundaries;
- 6 exact application-header cases across Chromium and Firefox for `/`, the canonical notebook
  route, and a 404 response;
- 4 Chromium axe cases covering `/`, the canonical notebook route, `/submit`, and `/login` with
  WCAG 2.0/2.1/2.2 tags and no serious or critical findings.

The first runs correctly exposed and then verified fixes for two defects: Next supplied the visible
`@handle` route segment in encoded form, causing a false 404, and the homepage `In [12]:` prompt had
2.56:1 contrast. The latter now uses the existing `slate-500` token.

The axe run is an automated smoke baseline, not manual WCAG 2.2 AA conformance evidence. This
section records the merged application-origin baseline only; the later local
content-origin/capability/hostile-output proof is recorded separately in
[`M0.5.md`](./M0.5.md).
