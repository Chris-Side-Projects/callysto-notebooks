## Locally executable evidence

The gated `/m0/isolation-proof` harness binds the application to IPv4 loopback
`127.0.0.1:3100` and the content gateway exclusively to IPv6 loopback `[::1]:3101`, addressed in
browser capabilities as `localhost:3101`. The app-host alias at `127.0.0.1:3101` is tested
unreachable, so an application host-only cookie cannot reach the gateway through a second port. The
proof routes return 404 unless `M0_PROOF_ENABLED=1`.

The proof establishes:

- an application-owned, text-escaped cell shell with fixed review anchors;
- a per-response nonce CSP with no production `unsafe-inline` or `unsafe-eval` and only the exact
  content origin in `frame-src`;
- Ed25519 capabilities minted by an issuer holding only the private key and verified by a gateway
  holding only the public key;
- a gateway child that starts only with an exact public-verifier environment allowlist; injected
  database, R2, auth, and private-signing-key sentinels never reach that process;
- exact v2 capability binding to proof, output, render revision, the SHA-256 of the checked-in
  artifact index, audience, expiry, and preview draft generation, with signature tampering, stale
  index authority, and unknown outputs rejected;
- a server-controlled artifact map, exact MIME types, `nosniff`, `private, no-store`, no CORS,
  no cookies, and neutral errors;
- an empty iframe sandbox, opaque storage origin, no referrer, and hostile HTML/SVG attempts unable
  to execute scripts or event handlers, read app storage/cookies, submit forms, open popups, navigate
  the top page, or obtain a canary response;
- near-viewport capability issuance and a later output receiving a fresh capability after the first
  lifetime;
- immediate denial of new issuance after restriction, replacement of a live iframe with a neutral
  unavailable state at refresh, expiry of an already issued bearer within the configured public
  bound, and explicit new-token-only restoration.

The production-server security command runs 14 cases serially across Chromium and Firefox:

```bash
npm run build
npm run test:security
```

Result on 2026-07-20: **14 passed**. Unit coverage adds seven capability serialization, authority,
expiry/lifetime, canonical-shape, tamper, and draft-boundary cases. A final manual harness smoke
returned HTTP 200 from the application, HTTP 204 from the direct and advertised gateway health
endpoints, and a refused connection for the unsafe `127.0.0.1:3101` app-host alias; the harness was
then stopped. A Playwright CLI full-page inspection also confirmed that the application shell and
isolated frames render; its disposable local screenshot is `output/playwright/m0-isolation-proof.png`.

The test harness uses three-second public and five-second preview lifetimes so real wall-clock
expiry, late loading, restriction, and restoration are exercised without a minute-long suite. The
configuration parser enforces the product maxima of 60 seconds public and 300 seconds preview.

## Cloudflare Worker source contract

[`infra/cloudflare/content-gateway/worker.ts`](../../infra/cloudflare/content-gateway/worker.ts)
adds a deployment-shaped but locally tested Worker contract. Eight focused integration cases prove
issuer-to-Worker URL/index interoperability, canonical Ed25519 v2 authority, exact
output/revision/content-index binding, duplicate-key and non-canonical-index rejection,
gateway-current-time 60/300-second limits even at the issuer clock-skew boundary,
cookie/method/path rejection, a strict content-addressed render index whose exact bytes are
re-hashed before parse, rejection of index substitution before artifact access, deterministic
server-derived artifact keys, artifact count/size/MIME bounds, byte-size and SHA-256 verification,
neutral failures, no `Set-Cookie`, `private, no-store`, and the accepted isolation headers:

```bash
npm run test:content-gateway:proof
```

Result on 2026-07-21: **8 passed** using only the local in-memory object store.

The test object store deliberately exposes only `get`. This proves that the Worker source does not
need list/write/delete, but it does not prove that a normal Cloudflare R2 binding is restricted to
that interface at the provider boundary. The checked-in Wrangler file is explicitly
local-contract-only, has no R2 binding, and is neither a deployment configuration nor a secret
store.

## Evidence boundary

This is a local proof using synthetic artifacts and loopback hostnames. It does **not** establish:

- a deployed Cloudflare Worker, provider-enforced read-only/no-list R2 identity, or content
  hostname;
- real registrable-domain cookie behavior;
- provider/CDN cache behavior or propagation latency;
- staging revocation within 60 seconds;
- a production key-management or rotation procedure; or
- scientific correctness, notebook execution, or a production renderer.

T003's local feasibility question is closed. The deployed content-host and provider propagation
checks remain part of the M0 cloud gate and must pass before M1 or production authorization.
