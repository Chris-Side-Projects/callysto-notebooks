# M0.5 application/content isolation evidence

- Status: **APPLICATION HEADER BASELINE ONLY; T003 OPEN**
- Last updated: 2026-07-20

Implemented locally:

- application CSP with `frame-ancestors 'none'`, `frame-src 'none'`, and `object-src 'none'`;
- `nosniff`, `DENY`, strict-origin referrer, permissions, opener, and origin-agent headers;
- exact Playwright response-header assertions on `/`, a canonical notebook route, and a 404 in
  Chromium and Firefox, passing against both development and optimized production servers.

Not yet implemented or verified:

- app-owned cell shell with a separately hosted cookieless rich-output frame;
- capability signing bound to exact artifact and active render revision;
- public/preview expiry, on-demand refresh, long-notebook lazy output loading, and `no-store`;
- hostile script/SVG/form/navigation/fetch/storage/cookie fixtures in Chromium and Firefox;
- ≤60-second restriction/revocation evidence;
- a staging content origin with exact MIME and cache behavior.

The current app CSP intentionally allows no output frames and still contains `unsafe-inline` for
script/style compatibility. T003 must replace that provisional application policy with a proven
nonce/hash strategy while adding the separately constrained content origin; it must not solve
rendering by broadening application-origin trust. Exact application headers do not complete M0.5.
