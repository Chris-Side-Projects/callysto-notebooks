## PostgreSQL lease and generation fencing

[`proofs/m0/postgres/lease-fencing-proof.sql`](../../proofs/m0/postgres/lease-fencing-proof.sql) is
explicitly proof-only DDL. The Vitest harness refuses missing, non-loopback, or non-dedicated
database targets, creates a unique schema, and removes it after the run.

Against a fresh local PostgreSQL 17.9 database, four cases prove:

- two concurrent workers use `FOR UPDATE SKIP LOCKED` and claim different jobs while one lock is
  held;
- lease timestamps and expiry are authored by PostgreSQL `clock_timestamp()`;
- lease tokens are database-random UUIDs and lease generations increase monotonically;
- an expired lease is reclaimed and its stale worker cannot complete;
- every case starts from an empty proof table and asserts the exact job claimed, so expired rows from
  an earlier case cannot satisfy a later assertion;
- an exact repeated completion with the same canonical result-manifest SHA-256 is recognized as an
  idempotent duplicate, while a conflicting result under the same completed lease fails closed; and
- replacing the active upload/draft generation fences the old worker before the replacement claim
  completes.

Run only against a disposable dedicated database:

```bash
CALLYSTO_TEST_DATABASE_URL=postgresql://USER@127.0.0.1:PORT/callysto_m0_proof \
  npm run test:postgres:proof
```

Local result on 2026-07-20: **1 file, 4 tests passed**. The checked-in CI workflow also defines a
digest-pinned PostgreSQL 17.9 service and this command. The same proof passed in pull-request Actions

## Credential-minimized converter process

The launcher and CLI under [`python/callysto_m0`](../../python/callysto_m0) use only the Python
standard library and the existing default-deny converter. The launcher supplies one explicit local
`.ipynb` path, one empty output directory, and a bounded version ID. It starts isolated Python mode
with a constant `LANG`/`LC_ALL`/`TZ` environment, no stdin or shell, captured output, and closed
descriptors. It rejects any child response that is not one exact, duplicate-key-free success or
error result shape, including nested field names, types, identifiers, digests, and fixed relative
paths. The child replaces its environment again, closes non-stdio descriptors, rejects
symlink/non-file inputs, bounds source bytes, never executes notebook code, and writes canonical
0600 results using fixed/digest-derived names.

The hostile sentinel fixture would read injected database/AWS/custom secrets, write a marker, and
make a network request if executed. The process cases prove:

- the marker is absent and active output becomes a placeholder;
- a direct invocation that bypasses the launcher still scrubs injected credentials, closes a real
  inherited file descriptor, and reports only the three constant environment names;
- two different injected secret/path sets produce identical manifests and results;
- no injected value appears in files, stdout, or stderr;
- a nonempty output directory fails with a named path-free error and preserves existing bytes;
- malformed, duplicate-key, extra-field, missing-field, wrong-type, unsafe-path, and wrong-digest
  child responses fail the launcher protocol; and
- the package initializer is inert and the complete transitive project-local child module graph
  contains no execution, subprocess, or network import/call path.

Together with cell-ID, conversion, and SQLite reference cases:

```bash
npm run test:python
```

Local result on exact Python 3.14.6 on 2026-07-21: **41 Python tests passed**, followed by the independent Node
cell-ID vector consumer.

## Disposable-provider converter feasibility

A real ephemeral Vercel Sandbox proof ran one converter happy path with a deterministic,
digest-pinned CPython 3.14.6 image. The actual converter ran as UID 65532 with a read-only root,
dropped capabilities, `no-new-privileges`, `--network none`, bounded PIDs/address space/CPU/wall
time, exact mounts, no secret environment, deterministic retry, and digest verification. Every
Sandbox and snapshot was then deleted and independently reconciled.

The proof also found that the **outer** Vercel Sandbox accepted a TCP connection to
`169.254.169.254:80` despite provider `deny-all`. The inner Docker `--network none` probe denied both
metadata and public IP access, so the bounded happy-path feasibility claim is supported. The same
outer runtime is rejected for a credential-bearing orchestrator because it cannot satisfy the
accepted PostgreSQL/R2-only invariant.

The retained provider output predates the strengthened literal execution-marker, controlled
zero-hit canary, unexpected-FD, Docker-runtime identity, and harness-identity assertions. The
current harness contains and locally contract-tests those checks, but its external replay requires
explicit approval to transmit the proof image/harness/fixture to Vercel and has not run. Exact old
allowlisted output, image inputs/digests, cleanup evidence, and non-claims are in
[`M0-vercel-sandbox-converter.md`](./M0-vercel-sandbox-converter.md).

## Evidence boundary

The local child protocol deliberately records `evidence_level=local_process_only` and
`network_boundary=not_enforced_by_os_or_container`; the separate Vercel/nested-container record is
only a disposable-provider happy-path slice. Together, the current evidence does **not** establish:

- the full deployed converter hostile MIME, canary/marker, unexpected-FD, size/limit/timeout,
  deterministic-failure, cleanup, and retry acceptance matrix on the current harness;
- an orchestrator limited at the infrastructure layer to PostgreSQL and private R2;
- denial of cloud metadata for a credential-bearing outer/orchestrator runtime;
- Railway process isolation, R2 credentials, a complete staging topology, or recovery; or
- production migrations or job orchestration.

T004 remains open at both the complete deployed converter acceptance matrix and the orchestrator
deployment boundary. Railway compute and Vercel Sandbox orchestrator placement are rejected by
current evidence. Select a platform that proves exact PostgreSQL/R2-only egress with metadata
denial; do not weaken D013.
